1.1.1
@@@@@

Version 1.1.1 is a **patch** release that modernizes the Cat-VRS build pipeline and
refreshes its imported dependencies. It is a patch — not a minor — release because the
schema changes are non-breaking (they only widen what validates) and there are no
breaking changes to any **trial use** :ref:`maturity <maturity-model>` classes. There are
no additions or removals to the set of Cat-VRS product features.

Patch changes
#############

Two abstract compositions were opened, aligning with VRS's convention of leaving abstract
base classes open for third-party extension. Both changes are non-breaking — they only
widen what validates, so every previously valid instance remains valid:

- :ref:`Constraint` (**trial use**): the abstract base no longer composes its concrete
  subtypes through a ``oneOf`` discriminator and is left open. The concrete Constraint
  subtypes still ``inherit`` from it and are otherwise unchanged.
- :ref:`Adjacency Constraint <AdjacencyConstraint>` (**draft**): the ``adjoinedElements``
  item schema uses ``anyOf`` instead of ``oneOf``. VRS renders its abstract base classes
  (e.g. :ref:`Location`) as open subtype unions, under which an element intended as another
  branch (such as a :ref:`MappableConcept`) can also validate; ``anyOf`` avoids a spurious
  "matches more than one schema" error. This also affects the :ref:`Gene Fusion <GeneFusion>`
  recipe.

Dependencies
############

- The Cat-VRS schema identifier (``$id``) is now
  ``https://w3id.org/ga4gh/schema/cat-vrs/1.1.1/...``.
- Imported schemas were updated to :ref:`VRS <imported>` ``2.1.1`` and GKM Core ``1.2.1``.

Supporting changes
##################

The following **supporting** changes were made to Cat-VRS that do not impact the
Cat-VRS data model:

- Adopted the modernized GKM metaschema processor (``ga4gh.gkm.metaschema`` 0.4.5), with
  which the source YAMLs are compiled (``source2classes`` / ``source2splitjs`` / ``y2t``).
  Cross-schema references in the recipe definitions now use explicit ``$refCurie``
  (e.g. ``cat-vrs:CategoricalVariant``), as required by the stricter 0.4.x processor.
- Cat-VRS now generates and owns the documentation definitions for its imported VRS and
  GKM Core classes locally, rather than depending on the submodule's pre-generated
  definitions. Imported VRS class pages now link to the full definition in the latest
  `VRS specification <https://vrs.ga4gh.org/en/latest/>`_.

1.1.0
@@@@@

Version 1.1.0 is the second release of the Categorical Variant Representation Specification. Since 1.0.0, we have introduced two new data classes, enhanced our documentation and repository tooling, and published a preprint on the specification.

News
####

- The Categorical Variant Representation Specification manuscript has been submitted. Please cite `our preprint <https://www.biorxiv.org/content/10.64898/2026.02.10.705161>`_.

Minor changes
#############

The following **product features** at **trial use** :ref:`maturity <maturity-model>` were modified:

- :ref:`Defining Allele Constraint <DefiningAlleleConstraint>` `relations` property is a :ref:`Mappable Concept<MappableConcept>`, and now requires the *type* field (`#246 <https://github.com/ga4gh/cat-vrs/pull/246>`_)
- :ref:`Defining Location Constraint <DefiningLocationConstraint>` `relations` and `matchCharacteristic` properties are :ref:`Mappable Concepts<MappableConcept>`, and now require the *type* field (`#246 <https://github.com/ga4gh/cat-vrs/pull/246>`_)
