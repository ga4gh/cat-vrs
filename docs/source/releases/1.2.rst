1.2
!!!

1.2.0
@@@@@

Version 1.2.0 modernizes the Cat-VRS build pipeline and advances its imported
dependencies to the 2026-09 ballot line. There are no additions or removals to the set of
Cat-VRS product features.

Schema changes
##############

The following **product feature** at **trial use** :ref:`maturity <maturity-model>` was modified:

- :ref:`Constraint`: the abstract base is now declared ``sealed``. The metaschema processor
  renders it as a closed union of its concrete subtypes with a ``type`` discriminator
  (matching the VRS abstract-class convention). The set of valid Constraint subtypes is
  unchanged, so the change is non-breaking.

Dependencies
############

- The Cat-VRS schema identifier (``$id``) is now
  ``https://w3id.org/ga4gh/schema/cat-vrs/1.2.0/...``.
- Imported schemas were advanced to :ref:`VRS <imported>` ``2.1.1`` and GKM Core ``1.3.0``.

Supporting changes
##################

The following **supporting** changes were made to Cat-VRS that do not impact the
Cat-VRS data model:

- Adopted the modernized GKM metaschema processor (``ga4gh.gkm.metaschema`` 0.4.8), with
  which the source YAMLs are compiled (``source2classes`` / ``source2splitjs`` / ``y2t``).
  Cross-schema references in the recipe definitions now use explicit ``$refCurie``
  (e.g. ``cat-vrs:CategoricalVariant``), as required by the stricter 0.4.x processor.
- Cat-VRS now generates and owns the documentation definitions for its imported VRS and
  GKM Core classes locally, rather than depending on the submodule's pre-generated
  definitions. Imported VRS class pages link to the full definition in the latest
  `VRS specification <https://vrs.ga4gh.org/en/latest/>`_.
